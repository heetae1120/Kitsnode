# 회원 광고 성과 경로 검증 준비

2026-11-21에 운영 Supabase Edge `kitsnode-ad-api` v16의 배포 소스와 공개된 호출 경계를 읽기 전용으로 확인했다. `/performance`와 `/shopping-catalog`에 허용 출처를 넣고 인증 없이 POST하면 각각 애플리케이션의 `unauthenticated` 401이 반환되고 임의의 경로는 404였다. 이는 라우팅·인증 경계의 관찰이며, 인증된 사용자의 데이터 조회 성공을 뜻하지 않는다. 비밀값과 사용자의 토큰은 수집하거나 기록하지 않았다.

## 서버의 확인 범위

- 인증은 Supabase Auth `getUser`를 통하며 익명 사용자·차단된 사용자를 거부한다. 회원 약관·개인정보 동의의 지정 버전을 조회한다. 이 경로는 새 광고 연결 사전 동의 기록을 검증하지 않는다.
- `kits_ads_list`, `kits_ads_get_binding`은 운영 DB에서 anon·authenticated 직접 실행 권한이 없고 service_role만 실행할 수 있으며, 두 RPC는 요청한 회원 ID를 기준으로 레코드를 제한한다. `get_binding`은 `read_connected`만 반환한다.
- 성과 요청은 승인된 회원 본인의 연결을 조회하고, 네이버 응답의 캠페인→광고그룹→상품 또는 키워드 관계를 각각 확인한다. 응답 전 회원 자격과 연결 revision/customer ID를 재확인한다. 관리자의 타 회원 조회는 구현되지 않았다.
- `/shopping-catalog`은 `KITS_SHOPPING_PREVIEW_ENABLED`로 노출되며 같은 플래그는 읽기 전용 미리보기·비교·순위 추정 경로도 함께 노출한다. `shopping-shadow`는 별도 `KITS_SHOPPING_SHADOW_ENABLED`가 필요하다. 필요한 라우트만 공개하는 별도 게이트 분리를 검토해야 한다.
- 현재 통계는 선택한 상품 또는 키워드 **하나**, 최대 31일(차이 30일)의 합계다. 반환값은 노출, 클릭, 광고비, 클릭률, 평균 클릭비용이다. 계정 전체 합계나 일자별 추이·구매 전환 지표가 아니다. 프론트의 두 막대 그래프는 합계 비교이며 시계열 그래프가 아니다.
- Auth `getUser`는 계정 식별을 확인하지만 이 경로는 매 요청마다 `auth.sessions`의 활성 여부를 별도로 확인하지 않는다. 사용자가 로그아웃하거나 동의를 철회하는 동안의 처리는 운영 가입·탈퇴 정책과 함께 실제 세션에서 확인해야 한다.

## 임시 진단 화면

`/store/ads/diagnostic/`에 기존 `AdPerformancePanel`을 추가했다. 기본 비활성 `NEXT_PUBLIC_AD_DIAGNOSTIC_PAGE_ENABLED`가 `true`일 때에만 표시되며, 별도 서버 구현 없이 실제 고객 화면과 같은 `shopping-catalog`와 `performance` 클라이언트를 사용한다. `NEXT_PUBLIC_AD_PERFORMANCE_ENABLED`가 켜져 있어야 한다. 페이지 플래그나 숨긴 URL은 권한 경계가 아니며 각 API가 서버에서 회원과 소유권을 검증해야 한다.

기존 키츠노드 운영자/테스트 회원으로 로그인한 뒤 본인의 연결만 목록에 나타나는지 확인하고, 종류·연결·캠페인·광고그룹·상품 또는 키워드와 기간을 선택해 조회한다. 기간에 실제 데이터가 없는 경우 `no_data`와 오류를 구분한다. 다른 회원의 연결은 테스트용 별도 세션에서 보이지 않는지 확인하고, 미인증 호출과 잘못된/타인 연결·대상 요청은 서버에서 거부되는지 확인한다. 일반 회원 대상 활성화 전에 기존 개인정보 동의와 광고 연결 사전 동의의 범위를 별도로 연결해야 한다.

격리 브라우저에서 합성 회원·모의 서버를 사용한 전체 카탈로그→성과 표시 및 목록 로딩 중 선택 비활성화가 통과했다. 실제 네이버 캠페인 하나의 통계 접근은 별도 일시 관리자 진단으로 확인되었으나, 이 회원 경로의 실제 연결·계층 선택·상품 또는 키워드 성과는 아직 확인되지 않았다. 진단 후 페이지 플래그를 `false`로 복구하고 배포 결과를 확인한다.
