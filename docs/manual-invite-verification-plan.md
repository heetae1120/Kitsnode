# 수동 초대 광고계정 연결 검증 후보

광고주가 이미 키츠노드에 네이버 권한을 부여한 경우에도 초대 재발송 없이 연결 확인을 요청한다. 광고주는 계정 ID를 입력하지 않는다. 운영자는 요청과 광고계정의 관계를 확인한 뒤 계정을 지정하고, 기존 확인 기록과 승인 절차로 연결한다. 연결이 확인되면 기존 광고 성과 화면에서 조회한다.

## 적용 및 실제 시험 전 확인

- 운영 DB의 현재 스키마와 `20261125073836_manual_advertiser_invite_request.sql`을 비교하고 적용 범위 및 복구 방법을 검토한다. 테스트용 요청·연결·확인 기록이 운영 DB에 생성된다.
- 기존 Edge 함수 v25와 후보 차이를 재검토하고, 기능을 기본 비활성인 상태로 배포한다. 기존 광고 조회와 회원 기능이 유지되는지 확인한다.
- 운영자 계정 권한, 서버 `KITS_AD_MANUAL_INVITE_REQUEST_ENABLED`, 프론트 `NEXT_PUBLIC_AD_MANUAL_INVITE_REQUEST_ENABLED`, 운영자 검토 페이지 활성 설정을 확인한다. 시험 전 활성화 범위와 종료 방법을 정한다.
- 지정된 유니킴 광고계정의 기존 키츠노드 운영 관리 권한을 그대로 사용한다. 재초대나 네이버 권한 변경은 하지 않는다. 광고주 로그인, 운영자 승인, 계정 관계 확인과 API 접근을 각 단계에서 확인한다.
- 운영 DB 및 함수 변경은 별도 명시적 승인 후 실행한다. 실제 데이터를 표시하면 광고주에게 해당 화면에서 확인받는다.

## 격리 검증

로컬 PostgreSQL 경합·권한 시험, 모의 서버 전체 흐름, 브라우저 요청·검토 화면, 타입 검사 및 빌드를 실행한다. 격리 검증은 실제 네이버 인증과 운영 설정의 성공을 보장하지 않는다.
