# 키츠노드 고객 회원탈퇴 상태

2026-11-23: 로그인한 고객이 확인 팝업에서 탈퇴를 선택하면 서버가 로그인 세션의 사용자만 처리한다. 별도 이메일 재인증은 요구하지 않는다. 관리자는 서버의 운영자 설정과 서버 소유 권한 정보로 보호하며 설정이 없거나 잘못되면 탈퇴를 허용하지 않는다.

- Supabase의 단일 트랜잭션은 고객 소유 광고 연결과 관련 데이터를 정리하고 Auth 계정을 삭제한다. 회원 프로필, 동의, 인증 연결과 세션은 계정 삭제에 따라 정리된다. DB 내 다른 서비스가 같은 사용자를 실제 참조하는 경우에는 해당 요청을 중단해 다른 기록의 연쇄 변경을 막는다.
- 확장프로그램 설치 여부나 네이버 애즈 권한 해제는 탈퇴 조건이 아니다. 네이버 권한 해제 및 확장프로그램 삭제는 고객에게 직접 진행하도록 안내한다. 인트라넷의 API, 예약 또는 복구 기능은 이 탈퇴 경로에 사용하지 않는다.
- 운영 `kitsnode-member-withdraw` v4와 `20261123024759_customer_withdraw_no_intranet`을 적용했다. 익명 요청 401, 허용되지 않은 출처 403, 정상 preflight 204를 확인했다. 삭제 RPC는 service role만 실행할 수 있다.
- 운영에서 신규 시험 계정 한 명만 허용한 별도 임시 함수와 화면으로 실제 탈퇴를 확인했다. 시험 계정의 Auth 사용자·프로필·동의·세션·identity·광고 연결·신규 차단 마커는 0건이었다. 다른 Auth 계정 9명의 구성 해시와 다른 광고 연결 2건은 시험 전과 같았고 관리자 데이터도 유지됐다. 임시 함수는 410으로 종료했고 화면은 제거했다.
- 일반 고객용 v4는 위 시험과 동일한 삭제 핸들러 및 트랜잭션을 사용한다. 시험 후 배포한 v4에서 실제 다른 고객의 계정을 다시 삭제하는 검증은 하지 않았다. 실제 네이버 OAuth 탈퇴·재가입 역시 별도 실계정으로 시험하지 않았다.
- 통신 오류가 삭제 직후 발생하면 결과를 단정하지 않고 고객에게 처리 결과 확인 안내를 표시한다. 네이버 애즈 권한은 고객이 직접 해제해야 한다.
