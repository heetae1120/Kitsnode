# 광고주 사전 동의 연결: 운영 반영 전 점검

이 문서는 후보의 적용 순서다. 현재 운영 DB·동의 함수·자동 초대에는 적용되지 않았다.

## 확정된 후보 문서

- 키츠노드 자체 사전 동의 원문: `public/policies/advertiser-consent-2026-11-21-v1.txt`.
- 버전: `kits-ad-consent-2026-11-21-v1`.
- SHA-256: `270cca049e2dfafe9d0eb406ac0bfd84e82fdf1830e5b2e7c52e5e44aa239850`.
- 게시 후보 URL: `https://heetae1120.github.io/Kitsnode/policies/advertiser-consent-2026-11-21-v1.txt`.
- 파일의 정확한 UTF-8 바이트 해시를 확인한다. 본문을 수정하면 파일명·버전·해시도 새 값으로 바꾼다.
- 이 원문은 사용자가 지정한 키츠노드 사전 동의 범위다. 네이버에서 표시하는 회원 초대 정책 전문과 그 해시는 별개다. 현재 프론트 `policyUrl`은 `ads.naver.com`으로만 제한되므로, 자체 동의 원문 링크와 네이버 정책 링크를 서로 다른 설정과 의미로 분리해야 한다. 자체 동의 해시를 네이버 정책 전문 해시로 사용해서는 안 된다.

## 운영 반영 순서

1. 먼저 연결·분석 페이지의 미연결 기능을 비활성 상태로 유지하고, 실제 프론트의 자체 원문 링크·네이버 정책 링크 및 사용자에게 보이는 설명을 작성한다. 원문 공개 후 실제 URL의 바이트와 위 SHA-256이 일치하는지 확인한다.
2. 새 마이그레이션 `20261121055943_kitsnode_invite_consent_recording.sql`을 현재 운영 스키마와 재비교하고, 개발 DB에서 실제 PostgREST `service_role`만 RPC를 호출할 수 있는지, 인증 회원과 익명 역할은 직접 호출이 거부되는지 검증한다. 저장·예약 중 소유자 연결 해제와 세션 삭제를 경합시켜 DB 레벨에서 차단되는지 확인한다.
3. 새 함수 `kitsnode-ad-consent-api`만 독립 배포한다. 기존 `kitsnode-ad-api`는 덮어쓰지 않는다. 서버 설정은 `KITS_INVITE_CONSENT_VERSION`과 `KITS_INVITE_POLICY_DIGEST`에 위 자체 동의 문서 버전·해시를 사용한다. 표준 Supabase URL/anon/service-role 값은 서버에만 존재해야 한다. 사용자 비밀번호, 인증번호, 토큰이나 서비스 키는 기록·출력하지 않는다.
4. 공개 API에서는 실제 회원 연결을 먼저 신청하고 동의 저장을 호출한다. 이메일 회원과 네이버 회원 각각에 대해 로그인, 본인 계정, 다른 회원의 계정, 동의 철회, 세션 로그아웃, 회원 탈퇴를 실환경에서 검증한다. 새 계정의 `pending_review`는 연결 신청을 뜻하며 네이버 광고주 소유나 초대 수락을 증명하지 않는다. CORS·JWT·rate limit 실패 시에는 데이터가 기록되지 않아야 한다.
5. 실제 네이버 광고주 계정·키츠노드 회원·연결 신청·동의 버전·세션을 서버의 만료/단일 사용 기록으로 결속하는 확장 프로그램 신뢰 경로를 구현하고, `kitsnode` 운영 조회 역할 외 다른 요청은 거부한다. 실제 네이버 화면 정책 버전이 바뀌는 경우 재확인하도록 별도 정책 증거를 연결한다. 현재 이 경로, 네이버 실제 화면 ID 입력 원인, 중복 초대에 대한 서버 대사는 미완료다.
6. 관리자 분석은 서버 운영자 허용 목록과 고객이 승인받은 `read_connected` 연결, 현재 고객 동의 및 연결 버전을 검증하는 별도 라우트를 완성한다. 비관리자, 타 고객 계정, 연결 해제·동의 철회 이후 재조회가 차단되어야 한다. 현재는 캠페인 조회 서비스 모형만 있고 실제 승인 바인딩 저장소·HTTP는 없다. 사용자별 성과 대시보드 API도 운영에서 꺼져 있다.
7. 끝으로 회원·운영자 실제 세션에서 동의 기록→확장→초대 수락→서버 연결→데이터 조회를 각각 확인한 뒤에만 관련 프론트 플래그를 켠다. 시험용 확장과 임시 진단 화면을 Chrome 웹 스토어 게시본이나 실제 사용자 기능과 혼동하지 않는다.

## 장애·중단 시

서비스 함수는 독립되어 있어 비활성 버전으로 교체할 수 있다. 발송 여부가 불확실한 요청을 자동 재발송하지 않는다. `docs/invite-consent-rollback.sql`은 기록된 고객 동의를 삭제하므로 자동 장애 복구로 실행하지 않는다. 함수 중단, 처리 중 예약 상태와 동의 기록 보존 여부를 먼저 확인한 다음 운영자가 별도로 실행 여부를 결정한다.
