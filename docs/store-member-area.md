# 스토어 점검과 광고 성과 분석

## 현재 범위

이번 구현은 **공개 준비 안내와 합성 예시 화면**이다. 회원 인증, 광고 계정 연결, 개인 실적 조회 기능은 제공하지 않는다. 로그인 안내나 잠긴 실적 표시는 실제 인증·접근 권한 검사를 대신하지 않으며, 각 페이지는 직접 URL로도 열 수 있다.

프론트 `Kitsnode`와 어드민 `kitsnode_edit`에 같은 독립 화면 복사본을 두었다. 어드민 복사본에서도 링크가 존재하는 페이지로 이동하지만, 신규 `/store/` 페이지는 어드민 편집 목록과 LayoutChanges 발행 대상에 포함하지 않는다. 기존 백엔드, 서버 allowlist, 데이터베이스, 인증 설정은 변경하지 않았다.

## 페이지와 이용 흐름

- `/store/`: 스토어 현황, 예정된 회원 이용 순서, 광고·상품 분석 진입 안내.
- `/store/ads/`: 로그인·광고 연결 전 개인 실적 안내와 별도의 합성 예시 진입.
- `/store/ads/connect/`: 네이버 검색광고 연결 준비 안내. 연결 버튼은 비활성 상태다.
- `/store/ads/example/`: 공개 합성 예시 분석. 로그인이나 연결 완료로 처리하지 않는다.
- `/store/login/`, `/store/signup/`: 준비 중 안내. 이메일·비밀번호 등 입력 필드와 실제 제출 동작은 없다.
- `/store/sales/`: 별도 스마트스토어 주문·상품 연결을 위한 후속 영역 안내.

예정된 실제 이용 순서는 회원가입·로그인 → 광고 성과 분석 → 별도 광고 계정 연결 → 내 성과 확인이다. 현재는 안내와 예시 탐색만 가능하며, 단계 진행이나 인증 성공 상태를 만들지 않는다.

개인 실적은 `—`와 로그인·광고 연결 필요 문구로 표시한다. 실측 0으로 표현하거나 합성 데이터로 채우지 않는다. 합성 예시는 별도 페이지로 분리하고 제목, 배너, 요약, 차트와 표에 예시임을 표시한다.

## 합성 예시와 지표 정의

- 예시 기간은 2026-10-26부터 2026-11-01까지다. 실제 고객·스토어·광고 계정의 데이터가 아니다.
- 예시 7일과 마지막 1일을 선택할 수 있다. 일별 또는 선택 기간 전체의 시간대별 합계를 표시한다.
- 각 행은 KST(UTC+9) 기준 4시간 구간이다. 하루 6개 구간, 전체 42개 합성 행을 사용한다. 이는 실제 광고 API의 제공 단위나 지원 범위를 보장하지 않는다.
- 필터와 집계는 페이지 메모리에서 처리한다. 계정 인증, 광고 API 조회, 입력 데이터 수집, localStorage·sessionStorage 저장을 하지 않는다. 페이지·정적 자원 로딩과 일반 링크 이동은 별개다.
- 광고비는 VAT 제외, 구매전환 매출은 취소·반품 조정 전으로 가정한다. 이익이나 정산 금액이 아니다.

지표는 비율의 단순 평균이 아니라 원자료 합계로 계산한다.

- 평균 클릭 비용 = 광고비 ÷ 클릭수.
- 구매전환율 = 구매전환수 ÷ 클릭수 × 100.
- 구매전환당 비용 = 광고비 ÷ 구매전환수.
- 구매 ROAS = 구매전환 매출 ÷ 광고비 × 100.

빈 자료, 누락값, 0인 분모는 계산할 수 없는 값을 `null`로 두고 화면에서는 `—`로 표시한다. 실제로 주어진 0은 0으로 유지한다. 음수와 유한하지 않은 숫자는 거부한다. 전체 전환이나 종류가 불명확한 전환이 섞이면 이를 구매로 바꾸어 표시하지 않고 구매 지표를 비워 둔다. 광고비와 클릭수는 별도로 합산한다.

실제 전환 귀속 규칙은 적용하지 않았다. 시간대의 예시 수치 차이만으로 입찰·예산 변경을 권하지 않으며, 실제 연결 시 귀속 기간과 지연·표본을 함께 확인해야 한다.

## 프론트·어드민 호환성과 디자인

- `src/lib/store-navigation.ts`의 독립 `storeLinks`를 사용한다. 기존 `toolLinks`와 이를 사용하는 어드민 편집 목록은 유지한다.
- 양쪽 `ToolsHeader`의 스토어 점검 드롭다운에서 기존 p·small 안내 노드를 보존하고 뒤에 링크만 추가한다. 기존 형제 순서와 selector용 wrapper를 바꾸지 않는다.
- `src/app/store/`, `src/components/store/`, `src/lib/store-ad-performance.ts`, `src/lib/store-navigation.ts`를 양쪽에서 같은 내용으로 유지한다. 원격 설정 로더나 편집 전용 미리보기 코드를 서로 덮어쓰지 않는다.
- 신규 페이지는 기존 `/tools/`의 설정 소비·발행·방문 분석 경계 밖에 둔다. 기존 공통 상단바 편집 계약은 유지하며, `/store/` 페이지를 편집·발행하는 기능은 추가하지 않는다.
- 기존 어드민 디자인 토큰의 값을 `.store-theme` 범위로 복사하고 Button·Card·Badge·설명·focus 패턴을 신규 영역에서만 사용한다. Pretendard, 14px 설명, 44px 주요 버튼과 기존 색상·간격·반경 기준을 따른다. 기존 전역 CSS나 어드민 테마를 변경하지 않는다.
- 표는 작은 화면에서 내부 가로 스크롤을 제공한다. 차트의 같은 수치를 표로 읽을 수 있고, 필터 label, 표 caption·헤더, 키보드 focus와 본문 바로가기를 제공한다.

## 실제 서비스 제공 전 필요한 작업

다음은 미구현 후속 요건이며 이번 작업에서 설정하거나 활성화하지 않았다.

1. 회원 인증 백엔드와 회원별 데이터 접근 권한 검증. 프론트 표시뿐 아니라 모든 조회 API에서 권한을 검사해야 한다.
2. 서버 전용 인증 정보 보관·교체·폐기, 광고 계정 소유권 확인, 필요한 집계만 읽는 연결 기능. 비밀키를 브라우저나 공개 소스에 두지 않는다.
3. 조회 범위와 구매전환 종류, 귀속 기간, 전환 집계 시점, 시간대, VAT, 취소·반품, 수집 지연 정의.
4. 개인정보 처리 고지·필요한 동의, 보관·삭제 기간, 연결 해제와 데이터 삭제 정책.
5. 광고 성과와 별개인 스마트스토어 주문·상품 연결 계약. 광고 구매전환을 전체 주문 실적으로 간주하지 않는다.
6. 실제 실패·권한 만료·재연결·빈 결과 상태와 운영 환경 검증. 배포·자격 증명 설정·DB 변경은 별도 승인 후 진행한다.

## 검증 기록과 남은 제한

- 수정 후 원본 저장소의 전체 테스트는 프론트 203/203, 어드민 253/253 통과했으며 실패·skip은 없다. 신규 회원 영역 테스트 11개는 합계 계산, null·0, 전환 종류, 그룹별 합계, 경로 분리, DOM 순서, 비연동 상태, CSS 범위와 secondary hover 회귀를 검사한다.
- 코드 검토에서 secondary 버튼 hover의 우선순위 때문에 텍스트 대비가 2.81:1로 낮아지는 문제를 발견했다. 기본 hover에서 secondary를 제외하도록 수정하고 회귀 테스트를 통과했다. 브라우저에서는 일반 상태의 computed style을 확인했으며, 포인터를 올린 실제 hover 상태의 computed style은 검증하지 않았다.
- 깨끗한 격리 복사본에서 양쪽 최종 `npm run build -- --webpack`와 `npm run typecheck`가 통과했다. 최종 프론트 원본 코드·테스트 18개 파일과 성공한 프론트 빌드 복사본의 바이트 일치도 확인했다.
- 원래 프론트 작업 디렉터리의 `npm run typecheck`는 기존 `.next/dev/types/routes.d 2.ts`의 중복 LayoutProps 선언으로 실패했다. 기존 산출물을 삭제하지 않고 보존했으며, 격리 복사본의 성공과 구분한다.
- Chrome에서 프론트 7개 경로를 320px로 확인했다. 문서 가로 넘침이 없고 주요 버튼은 44px, input 요소는 0개였다. 회원가입·로그인·광고 연결·상품 연결 버튼은 비활성 상태였다. 390px 예시 표는 332px 영역 안에서 596px 내용을 내부 스크롤하며 문서 가로 넘침이 없었다. 광고 화면 760/1280px와 현황 화면 1512px도 가로 넘침이 없었다.
- 네이티브 기간 선택으로 마지막 1일의 광고비 206,200원·클릭 302회·구매전환 15건·매출 480,000원·ROAS 232.78%를 확인했다. 7일은 1,280,020원·1,862회·85건·2,720,000원·212.5%였다. 일별/시간대별에서 합계가 같고 시간대별 행은 6개였다. 새로고침하면 예시 7일·일별 기본값으로 돌아왔다.
- 모바일 도구 메뉴의 스토어 하위 링크 3개, Escape 닫기와 스토어 버튼 focus 복원, Enter 이동, Back/Forward, 본문 바로가기의 store-main focus를 확인했다. 어드민 복사본에서도 도구 → 광고 → 예시 탐색과 같은 합계, 320/390px 가로 넘침 없음을 확인했다.
- 양쪽 기존 안내 selector `body .tool-topbar > nav:nth-of-type(1) > div:nth-of-type(1) > div:nth-of-type(1) > p:nth-of-type(1)`가 각각 요소 하나에 일치했다. 과거 published patch의 실제 적용·제거와 모든 selector의 전수 검사는 수행하지 않았다.
- 별도 프론트 `PAGES_BASE_PATH=/kitsnode-qa`의 `npm run build -- --webpack`가 통과했다. 실제 `/kitsnode-qa/store/` → 광고 → 예시 이동·새로고침에서 접두 경로와 활성 메뉴가 유지됐고, 내보낸 현황 페이지에 접두 경로가 빠진 store href가 없음을 확인했다. 임시 서버 로그에서 `/favicon.ico` 요청 404가 1건 관찰됐으며 이번 범위에서는 수정하지 않았다. 모든 네트워크 요청의 성공을 검증한 것은 아니다.
- 최종 확인한 브라우저 로그의 error/warn은 없었다. 데스크톱·390px 스크린샷을 시각 검토했고 viewport를 1512px로 복원했다. 브라우저 네트워크·저장소 계측은 수행하지 않았으며, 데이터 요청·저장이 없다는 설명은 소스 검사에 근거한다. Safari·실제 iPhone·스크린리더 검증은 미실행이다.
- 사용자 확인용 로컬 미리보기는 프론트 `http://127.0.0.1:4321/store/`를 유지한다. 검증용 어드민 4322와 basePath 확인용 4323 서버는 종료를 확인했다. 기존 메인 어드민 `http://127.0.0.1:4315/editor/`는 그대로 두었다.
- 실제 회원 인증·광고 계정·개인 실적·운영 API 검증은 미실행이다. push·배포·운영 발행·DB 변경·자격 증명 생성이나 제공은 하지 않았다.
