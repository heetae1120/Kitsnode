# Cloudflare consent documents: release preparation

`bundled-terms.mjs` is intentionally empty. The service fails closed until both reviewed UTF-8 documents and their current DB pointers are configured. The endpoint returns separate `terms` and `privacy` documents; each acceptance is recorded by version. Test documents must never be deployed to public users. Document text is public, not a secret.

1. Review the final texts and assign distinct immutable versions. Every text change requires a new version. Use `node prepare-consent-bundle.mjs /path/terms.txt terms-version /path/privacy.txt privacy-version /tmp/reviewed-documents.mjs`; it refuses to overwrite an existing file. Review the generated module and printed digests before including it as `bundled-terms.mjs` in the approved release build.
2. Configure `MEMBER_TERMS_VERSION`, `MEMBER_TERMS_SHA256`, `MEMBER_PRIVACY_VERSION`, `MEMBER_PRIVACY_SHA256` to the printed values. Missing, altered, oversized, or mismatched content fails closed. The candidate DB schema also validates the active versions. Preserve reviewed source documents and release history.
3. Review and separately approve the DB migration, backup, active pointer setup, permissions, roll-forward and rollback. Existing single-document consent is not evidence of separately agreeing to two documents. A stale Worker must fail closed after current document pointers change. An alternative draft is retained under `review-drafts/` and is not a migration; do not apply it. Review the candidate migration before application.
4. Configure three unique Cloudflare bindings (`MEMBER_SITE_LIMIT`, `MEMBER_IP_LIMIT`, `MEMBER_ACCOUNT_LIMIT`), `MEMBER_EDGE_LIMITS_ENABLED=1`, a separate strong `MEMBER_RATE_LIMIT_SECRET`, Hyperdrive and other secrets. The site circuit breaker is a shared per-location emergency budget: distributed traffic can exhaust it for legitimate users. All Cloudflare quotas are approximate and location-specific, not globally strict. Login before session creation is limited by IP and site, not by verified account.
5. Confirm trusted ingress for the actual deployment, including Worker subrequests and service bindings, and use separate mitigation for distributed traffic. A Wrangler remote preview result does not prove direct workers.dev or same-zone subrequest behavior. Verify final limits and recovery with isolated load tests before separately authorized deployment. Keep email disabled until ready.
