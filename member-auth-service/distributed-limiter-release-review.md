# 회원 인증 전역 요청 제한 검토

상태: 격리 후보. `distributed-limiter-candidate.mjs`는 운영 경로에 연결되어 있지 않다. 클라이언트가 직접 Durable Object에 접근하지 않도록 하고, 실제 바인딩과 출시 수치는 별도로 검토한다.

## 설계와 검증

Cloudflare 위치별 IP 제한 이후 DB 접근 전에 하나의 SQLite Durable Object의 원자적 영속 카운터를 검사하는 안이다. 객체 호출 오류, 잘못된 응답 및 시간 초과 시 실패 처리한다. 고정 시간 창 방식은 경계에서 두 창의 허용량이 연달아 처리될 수 있으며, 시간 초과된 호출이 나중에 카운터를 소비할 수 있다. 변경된 한도 설정이 기존 상태와 일치하지 않으면 차단하므로 정책 변경 시 안전한 버전 전환 절차가 필요하다.

합성 임시 Worker에서 미국·독일·일본의 12개 측정 지점이 ORD/LAX/SEA/DFW/FRA/HAM/CDG/NRT의 8개 위치로 접근했다. 60초 전역 한도 5건에 대해 5건 200, 7건 429였다. 별도 소량 시험에서 준비 요청 1건 후 동시 24건 중 4건 허용·20건 거부를 확인했다. 모의 장애·응답 지연은 fail closed, 시험 저장소 초기화 후 정상 요청 재허용을 확인했다. 저장소 deleteAll, 클래스 삭제 마이그레이션 및 임시 Worker 삭제를 완료했다. 정상 사용자 공정성, 실제 객체 장애·복구와 대규모·장시간 부하는 검증하지 않았다.

## 운영 전 조건

- IP 신뢰 경계와 악의적 Worker subrequest 경로를 확인하고 지역별 IP 제한을 먼저 적용한다. 단일 전역 한도는 IP를 분산한 공격자에게 소진되어 모든 정상 사용자도 차단할 수 있다. 이 한도를 단독 방어 수단으로 사용하지 않는다.
- 실제 네이버 콜백, 로그인, 세션 확인, 로그아웃을 어떤 한도로 보호·구제할지 사용자 영향과 네이버 재시도를 포함해 결정한다. 공격 시 차단과 서비스 가용성 간 우선순위, 관측 가능한 지표·경보·복구, 스위치 및 변경 권한을 마련한다.
- 다중 지역 지연, 동시성 및 창 경계, 객체 오류·응답 지연·재시작·저장소 한도 소진을 격리 환경에서 시험하고 허용량을 실측 근거로 정한다. 전역 단일 객체는 지연·병목·단일 장애 지점이며 fail closed 정책에서는 객체 장애가 전체 인증 중단으로 이어진다.
- Workers Free에서 Durable Objects의 요청·시간·스토리지 한도 중 하나라도 초과하면 해당 작업이 실패할 수 있으므로 계정의 실제 요금제·한도·사용량과 공격시 소진 영향을 확인한다. [Cloudflare 비용 문서](https://developers.cloudflare.com/durable-objects/platform/pricing/)
- 개발 코드·DB·운영 설정을 배포하기 전 별도로 승인된 검토와 롤백을 준비한다. SENS 메일은 계속 비활성이다.
