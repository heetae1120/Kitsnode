# PostgreSQL support candidate

This is local preparation, not an enabled production service. The chosen Supabase project, hostname, role, network access and operational deployment remain unconfigured. Neither the server nor tests connect to a remote database or apply a production migration.

`../supabase/migrations/20261109142215_kitsnode_member_auth_support.sql` creates a private support schema with RLS enabled, no client policies and no PUBLIC grants. It has not been applied. The intended trusted backend-only role and schema ownership still need to be designed and verified in a staging project; a table owner can bypass RLS, and authorization relies on the trusted application server. Better Auth's own user/session/account/verification tables, schema, migration, roles and isolation are **not** created by this file. Do not expose this schema via the Supabase Data API.

`postgres-support.mjs` accepts an already-created `pg`-compatible query pool. It does not open a connection or run migrations. It provides immutable version/digest registration, per-user consent recording and atomic state-digest claims via unique constraints, plus an explicit expired-claim cleanup function. The 24-hour claim retention assumes the pinned Better Auth OAuth state lifetime is shorter; verify both before an upgrade and schedule secure cleanup separately. A durable pool with TLS certificate validation and suitable pooler mode, dedicated backend access, backups, privileges, record deletion and availability policies remain unimplemented.

`createPostgresMemberApp()` in `app.mjs` binds the consent store after a successful terms registration. It defaults email authentication to disabled, rejects startup if terms/schema/storage are missing, and denies the synthetic protected endpoint when the server-validated session does not have `emailVerified === true`. In particular, current Naver profiles set `emailVerified: false`; there is **no implemented verification or recovery UX** to change that yet, so do not claim Naver users can access private member data. Every real protected endpoint must apply an equivalent verified-session, current-consent and ownership policy. `claimState()` is not yet connected to an enabled production Naver provider.

`npm test` includes isolated in-memory PGlite tests for schema, concurrency, immutable terms, identity isolation and unauthorised schema access. They are not a substitute for actual PostgreSQL/Supabase role, RLS, network, multi-connection, backup or migration testing. Keep `server.mjs` fail-closed until the missing production authentication, policy, mail and deployment checks are complete. Never apply the SQL, provision credentials, or change operating databases without explicit approval.
