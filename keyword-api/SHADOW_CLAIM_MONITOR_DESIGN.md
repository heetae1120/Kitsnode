# 모의 예약 클레임 감시 개선안 — 로컬 검증 전용

기존 `service_role` 리뷰 RPC를 포함한 초안 SQL은 자동 적용을 막기 위해 `supabase/migrations`가 아닌 `keyword-api/test-fixtures/shadow-claim-outcome-monitor-candidate.sql`에만 보관한다. 이 파일은 격리 DB 테스트 전용이며 운영·시험 프로젝트에 적용해서는 안 된다. 이전 초안의 HTTP 리뷰 핸들러도 운영 라우트에 연결하지 않는다. 배포용 마이그레이션은 독립 신원·권한 경계를 검증한 후 별도로 작성해야 한다.

기존 예약 클레임 RPC와 그 응답은 그대로 두고 서비스 역할만 호출할 수 있는 v2 RPC를 추가한다. 기존 RPC를 먼저 실행한 뒤 결과가 없으면 동일 규칙·시간의 원장을 조회한다. 같은 시간의 정상 완료는 `already_recorded`, 사용자 동의 철회나 시간 종료 등으로 완료된 의도적 건너뜀은 `already_skipped`, 10분 미만의 작업 중 클레임은 `in_progress`로 분류한다. 10분 이상 `claimed` 또는 `uncertain`은 `unresolved`, 일치하는 원장이 없는 거부는 `rejected`다. 완료·건너뜀·진행 중은 재시도하지 않고 장애를 만들지 않는다. 새로 거부된 건은 실패로 감시한다.

로컬 후보는 예약 실행과 분리된 읽기 전용 검사기로 시작 시와 이후 60초 간격으로 10분이 지난 `claimed`, `uncertain` 및 예상치 못한 사유의 `skipped` 건수를 확인한다. 한 번에 DB 요청은 하나만 수행하며, 30초 응답 초과와 3분 검사 누락은 장애로 판단한다. 타임아웃은 DB 요청 취소를 뜻하지 않는다. 늦게 도착한 응답은 버리고 다음 조회의 성공으로만 회복하며, 응답이 계속 끝나지 않으면 중복 요청하지 않는다. 감독기는 모의 실행과 클레임 검사 상태를 독립적으로 판정한다. 경과시간 판정에는 단조 시계를 사용한다. 조건별 부분 인덱스와 조회 계획은 격리 PostgreSQL에서 시험했다.

클레임이 미해결이면 로컬 후보의 감독기는 정상 상태 표시 파일을 제거하도록 설계돼 있고, 기존 파일 감시를 통해 이메일 경보를 발생시키는 구성을 의도한다. 60초 조회 간격 외에도 요청·집계·클라우드 경보 조건에 따른 지연이 있으므로 10분이 되는 즉시 이메일이 온다고 보장하지 않는다. 10분 경과는 작업 취소나 최종 실패를 뜻하지 않는다. 마커 경로가 없거나 마커 I/O가 실패하는 경우 시작을 거부하거나 감독 프로세스를 실패 종료하는 보완은 로컬 시험 단계다. **위 60초 검사와 마커 보완은 현재 시험 서버에 배포되지 않았다.**

**운영자 검토 기록은 로컬 초안만 있다.** 별도 서버 핸들러가 검증된 Supabase 세션과 서버측 운영자 허용 목록을 확인하고, 선택된 클레임의 예상 상태·근거 참조번호를 service-role 전용 RPC로 전달한다. DB는 원장을 잠그고 상태·검토 자격을 다시 검사한 뒤 별도 테이블에 운영자·서버 시각·근거·관찰 상태를 기록한다. 원래 claim과 이력은 수정하거나 삭제하지 않고 재시도도 하지 않는다. **검토 기록만으로 경보 집계에서 제외하거나 경보를 해제하지 않는다.** 늦게 완료됐거나 앞으로 완료될 가능성이 있으므로 검토는 작업의 취소나 결과 확정이 아니며, 서버 API에서도 이를 별도로 확인받는다.

기존 검토 초안은 서버 애플리케이션을 신뢰한다. `service_role` 자격증명을 가진 별도 프로세스는 검토 RPC에 임의 운영자 ID를 전달하거나 테이블에 직접 삽입할 수 있으므로 DB 자체가 운영자 신원을 독립적으로 보장하지 않는다. 이를 보완하려고 Ed25519 서명, 일회성 도전값, 독립 resolver 역할과 별도 증거 등록 역할을 이용한 [격리 시험 후보](INDEPENDENT_OPERATOR_AUTH_DESIGN.md)를 만들었다. 해결 기록은 원장과 기존 이력을 보존하고, 해결 이후 늦은 저장을 트랜잭션에서 차단하도록 시험했다. 검토만으로 결과 확정이나 경보 해제를 뜻하지 않으며 자동 재시도도 하지 않는다.

격리 후보는 실제 전용 서비스·DB 자격증명 분리, 운영자 키 등록·철회, 신뢰할 증거 출처와 운영 승인 절차가 구축되기 전까지 운영 감사 증거 또는 경보 해제 수단으로 배포하지 않는다. DB 소유자나 독립 resolver 자체의 침해는 시험에서 방어하지 않는다. 세션 행 존재와 `not_after`만으로 Supabase의 비활성·단일 세션 정책 전체를 보장하지 않는다. 운영자 화면, 실제 라우팅·배포 및 사용자 대상 문구 검증은 아직 없다.

로컬 PostgreSQL·HTTP 시험은 중복 클레임과 권한 철회, 실제 Ed25519 서명·재사용 거부, 별도 DB 역할, 늦은 이력 저장 차단과 경쟁 상태를 확인했다. 실제 Supabase Auth의 임시 시험 사용자 JWT를 로컬 HTTP·서명·격리 DB와 연결하는 시험도 수행했으며, 로컬 DB 사용자·세션은 합성 복제본이다. 별도로 실제 `kits` Supabase의 일회용 시험 스키마·합성 데이터 트랜잭션에서 역할 제한, 해결 및 늦은 저장 차단을 시험하고 롤백했다. 이 원격 DB 시험 자체는 실제 JWT·서명 검증이나 독립 서비스의 운영 배포를 입증하지 않는다. 실제 자동 입찰은 중단 상태다.
