# 미완료 클레임 해결: 독립 운영자 증명 시험 설계

이 파일과 관련 코드는 **격리 테스트용**이며 실행 중인 감독기, Supabase 또는 사용자 화면에 연결돼 있지 않다. 실제 자동 입찰은 중단 상태다.

Supabase `service_role`은 Auth 관리 권한도 가질 수 있으므로, 작업 서버가 보유한 그 키로 확인한 사용자 JWT만을 독립 운영자 신원의 증거로 간주하지 않는다. 별도의 신뢰 경계에서 운영자가 보유한 개인키로 서명하고, 작업 서버와 자격증명·프로세스·접근권한이 분리된 검증 서비스가 등록된 Ed25519 공개키를 검증하는 구조를 시험한다. 개인키는 클라이언트에 남고 서명·공개키만 전달한다. 신규 키 등록·교체·철회는 별도 관리 권한과 대면 확인 등 독립된 절차가 필요하며 아직 구현하지 않았다.

서명 도전값에는 프로토콜 버전, 일회성 ID, 운영자 ID, 키 ID, 공개키 지문(SPKI DER의 SHA-256), 동작, 클레임 ID, 예상 상태, 사건 참조, 증거 SHA-256, 발급 및 만료 시간이 포함된다. 최대 유효시간은 5분이다. 검증기는 신뢰된 저장소에 보관된 도전값과 등록 공개키만 읽고, 사용자 입력으로 전달된 키는 신뢰하지 않는다. DB는 소비할 때 별도 resolver 역할만 허용하고 도전값·만료·미사용·키 활성상태 및 지문·예상 클레임 상태를 다시 검사한다. 도전값 소비와 해결 기록은 한 트랜잭션으로 처리하며 원래 클레임과 이력을 삭제하거나 재실행하지 않는다.

로컬 후보는 검증된 JWT의 `session_id`를 서명에 결합하고 DB가 해결 직전 계정·세션·운영자 허용 상태를 행잠금하여 재검사한다. 이 부분은 실제 Supabase Auth 스키마·권한과 배포 환경 검증 전의 모형이다. 로컬 후보의 별도 등록 역할은 제한된 증거 바이트를 저장하고, 해결 트랜잭션은 대상·사건·해시를 묶어 행잠금 후 내용을 다시 해시한다. 이는 격리 DB 모형이며 외부 실제 증거 저장소, 보존 보장, 신뢰할 수 있는 증거 등록·철회 절차가 구현됐다는 의미가 아니다.

Supabase 세션 행 존재 및 `not_after`만으로 비활성 타임아웃·단일 세션 정책 전체가 즉시 적용된다고 보장할 수 없다. 일부 정책은 토큰 갱신 시 적용되고 오래된 세션 행이 즉시 삭제되지 않을 수 있다. 실제 프로젝트의 Auth 정책과 만료·로그아웃·강제 종료 동작을 별도로 검증해야 한다.

격리 시험은 임시 키와 로컬 PostgreSQL을 사용하여 실제 서명 확인 → 별도 DB 역할로 도전값 조회 → 원자적 1회 소비·해결 기록을 연결하고, 잘못된 서명·재사용·공유 `service_role`의 직접 해결 호출을 거부한다. 별도 DB 시험에서 키 철회, 늦은 결과 기록의 롤백 및 동시 상태 변경도 확인한다. `node --test keyword-api/src/independent-operator-proof.test.mjs`와 `python3 keyword-api/test-fixtures/run-independent-operator.py`로 재현한다.

추가로 `kits`의 일회용 합성 인증 회원을 Admin API로 생성해 실제 JWT 발급·`getUser`를 확인하고, 같은 JWT를 로컬 HTTP·임시 서명 키·격리 PostgreSQL에 연결했다. 로그아웃 후 기존 JWT 요청이 거부되고 임시 사용자가 삭제된 것을 확인했다. 로컬 DB의 사용자와 세션 행은 실제 Auth에서 얻은 식별자를 복제한 **합성 데이터**이며 실제 Supabase DB에서 인증과 해결의 단일 트랜잭션이 검증됐다는 의미는 아니다. 테스트는 실제 서비스의 임시 Auth 사용자 생성과 서비스 역할 키가 필요하므로 무심코 재실행하지 않는다. 암호·토큰은 출력하지 않았고 임시 복구 파일은 정리됐다.

아직 **독립 서비스의 실제 배포·격리, 키 등록과 복구, 키 보관 장치 및 운영자용 서명 UI, 운영 접근 정책, 실제 Supabase JWT/세션 연동, 사용자별 권한 철회, 증거의 진위 확인과 승인 정책은 검증되지 않았다.** 공개키가 적절한 운영자에게 등록됐다는 절차의 신뢰성과 별도 서비스·DB 역할의 비밀 분리가 없으면 위 서명은 독립 신원 보증이 아니다. 데이터베이스 소유자·인프라 관리자와 분리 서비스 자체가 완전히 침해된 경우까지 방어한다고 주장하지 않는다. 해결 기록의 증거 해시는 문서의 실존이나 내용을 검증하지 않는다.

사후 확인을 위한 시험 후보는 실제 서명, 고정 도전값 필드와 검증에 사용된 공개키를 접근이 제한된 별도 기록에 보존한다. 공개키 등록·철회 이벤트는 독립 관리 역할이 남겨야 하며 resolver는 키 등록이나 폐기를 변경할 수 없어야 한다. 보존된 값만으로는 등록 당시 실제 운영자와 키의 관계, 관리자 권한을 가진 주체의 변경 여부, 증거 원본의 실재가 증명되지 않는다. 특히 DB 소유자는 내용을 변경할 수 있으므로 외부의 독립적 WORM 보관·키 관리 및 서명 시각 검증 등 없이는 위변조 불가능한 운영 감사 기록으로 취급하지 않는다. 서명과 증거 세부정보, 개인키를 로그에 남기지 않는다.
