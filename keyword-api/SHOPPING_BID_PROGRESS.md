# 쇼핑검색 모의 입찰 개발 상태

2026-11-17 유니킴 연결 계정을 읽기 전용으로 확인했다. 캠페인 4개와 광고그룹 40개가 쇼핑검색 유형이며 모두 중지 상태였다. 상품 소재 40개는 모두 그룹 입찰가를 상속했고 네이버 자체 자동입찰은 비활성이었다. 키워드 0건은 상품 소재를 사용하는 쇼핑검색 유형의 특성을 함께 고려해야 한다. [광고그룹 안내](https://ads.naver.com/help/faq/1508)

## 구현과 검증

- `/store/ads/simulation/`에서 승인된 연결 계정, 캠페인, 그룹, 상품을 선택하고 직접 입력한 기준값과 한도로 가상 입찰가를 확인한다.
- Edge API의 `/api/shopping-catalog`, `/api/shopping-bid-preview`는 인증·회원 동의·소유자별 연결과 네이버 계정 및 계층 관계를 확인한다. 네이버 요청은 GET만 사용하고 조회 후 연결 상태를 다시 확인한다.
- 그룹 입찰가를 상속하는 상품은 그룹 기준으로 계산한다. 소재 전체 목록의 완전성을 확인할 수 없으므로 영향을 받는 전체 상품 수는 미확인으로 표시한다.
- 중지된 캠페인·그룹도 가정값을 계산하되 차단 사유와 실행 불가 상태를 표시한다. 사용자가 입력한 기준값은 네이버의 추정 입찰가나 순위 보장이 아니다.
- 실제 유니킴 계정에서 임시 읽기 전용 검증으로 캠페인 4개, 선택한 캠페인의 그룹 10개, 선택 그룹의 상품 1개를 조회하고 현재 50원, 가정 기준 60원의 모의 결과를 확인했다. 결과에는 캠페인·그룹 중지와 상품 전체 범위 미확인 사유가 포함됐다. 별도 임시 검증에서는 실제 회원 세션 대신 해당 회원의 고정 ID를 사용했고 DB 연결·동의 및 네이버 조회를 확인했다.
- 브라우저 화면 전체 흐름은 가상 인증·네이버 응답으로 검증했다. 실제 회원 세션을 사용하는 새 화면의 운영 환경 전체 흐름은 아직 검증하지 않았다.

기존 모의 입찰 화면과 API는 운영에 배포됐다. 자동 실행 및 네이버 입찰가 변경은 구현 경로에서 제공하지 않는다. 조건부 변경 보장과 그룹 소재 목록 완전성 등을 확인하기 전에는 자동 실행을 켜지 않는다.

## 2026-11-17 영향 범위 개선 개발본

모의 결과에 조회된 소재의 이름·소재 ID·상태와 그룹 입찰가 상속 여부를 표시하고, 상속·개별 입찰·미확인 건수를 구분한다. 소유 계정·광고그룹 불일치와 중복 소재는 거부하며, 상품형 소재 1,000건까지 받아 1,000건 초과 시 일부 목록을 전체처럼 표시하지 않고 거부한다. 네이버의 [쇼핑몰 상품형 도움말](https://ads.naver.com/help/faq/1308)은 그룹당 최대 1,000개 등록을 명시한다. 이는 등록 상한이지 API 응답 한도 보장은 아니다. 네이버 응답 본문의 별도 8MB 제한을 초과해도 안전하게 조회 실패로 처리한다. 변경은 아직 로컬 개발본이며 운영에 배포하지 않았다.

네이버의 [소재 조회 명세](https://naver.github.io/searchad-apidoc/#/operations/GET/~2Fncc~2Fads%7B%3FnccAdgroupId%7D)는 그룹별 목록 반환을 설명하지만, 응답 총건수·잘림 여부와 상한에 관한 보장은 확인되지 않았다. 따라서 반환된 목록은 조회된 소재로만 설명하고 `affectedProductCount`는 미확인으로 유지한다. 조회 후 소재 상태는 변할 수 있다. 전체성 보장은 네이버 공식 답변이나 문서로 확인해야 한다.

운영 네이버애즈에서 유니킴 `01. QP1000C`의 `test_01` 그룹을 확인한 결과, 소재 목록에는 한 건이 표시되고 해당 소재는 기본 입찰가 50원을 사용한다. 이는 이전 API에서 조회한 동일 그룹 한 건과 맞지만, 다른 그룹이나 응답 한도에 관한 보장은 아니다.

## 마스터 보고서 대조와 자동 입찰 준비

네이버의 [ShoppingProduct 마스터 명세](https://gist.github.com/naver-searchad/186ca42e1e8596b0e3dcf74e3a86c04f)는 고객·그룹·소재 ID와 그룹 입찰가 상속 여부, 등록·삭제 시점을 포함한다. `shopping-master-report.mjs`는 마스터 생성·상태 확인·네이버 고정 주소 다운로드·TSV 파싱을 제공한다. `shopping-master-compare.mjs`는 서버에서 회원 동의와 소유 연결 및 캠페인·그룹을 검증한 뒤 보고서와 실시간 목록을 비교한다. `shopping-shadow-run.mjs`는 두 목록의 소재 ID와 상속 여부 차이를 검출한다. 일치하더라도 전체성 또는 동일 시점을 보장하지 않는다. 재사용 경로는 로컬 개발본이며 운영 API나 화면에 연결하지 않았다.

2026-11-17 생성된 유니킴 ShoppingProduct 보고서(기준시각 13:59 KST)를 실시간 API와 일회성 임시 서버로 대조했다. 쇼핑검색 캠페인 4개·광고그룹 40개에서 양쪽 모두 소재 40건, 그룹 기본 입찰가 상속 40건이며, 40개 그룹 모두 ID와 상속 여부가 일치했다. 보고서에서 해당 그룹들의 삭제 소재는 0건이었다. 검사 대상 캠페인·그룹은 중지 중이며 광고 집행 여부와 소재 존재는 별개다. 이 결과는 조회 시점에 한정되며 반환 완전성 또는 원자적 갱신을 보증하지 않는다.

같은 모듈의 예행 계획은 가상 금액과 차단 사유만 반환한다. 스케줄러, DB, 운영 API, 쓰기 어댑터는 연결하지 않았으며 항상 `execution: disabled`이다. 원자적 조건부 입찰 변경의 네이버 지원이 확인되지 않았으므로 실제 자동 실행은 금지 상태다.

네이버에 확인할 사항: 1) `/ncc/ads?nccAdgroupId=`의 반환 최대값, 잘림 표시와 조회 가능한 소재 상태·삭제 처리, 2) ShoppingProduct 전체 보고서의 생성 기준 시점·완전성·삭제 처리 및 실시간 변경과의 일관성, 3) 입찰가 변경 시 기존 값 또는 버전에 대한 원자적 조건부 갱신 지원. 확인 전에는 대조 일치를 전체 범위 확인이나 실행 승인으로 취급하지 않는다.

## 모의 규칙·이력 개발본

광고그룹별 수동 기준 입찰가·최소/최대 금액·한 번에 변경할 최대 금액을 규칙으로 저장한다. 실행은 요청 시 마스터 대조와 새 소재 조회를 수행하는 모의 계산이며 결과·규칙 당시 금액·대조 상태·차단 사유를 이력에 남긴다. 예약 실행, 자동 실행 활성화, 네이버 입찰 쓰기 경로는 없다. 비교가 일치해도 전체성 미확인과 원자적 입찰 변경 미확인 차단을 유지한다. 마스터 보고서 중복 생성 방지를 위해 기존 계정별 2분 제한이 적용된다.

규칙과 이력은 전용 비공개 DB 테이블과 서버 전용 함수로 설계했으며, 연결 철회·규칙 버전 충돌을 이력 저장 시 다시 확인한다. 규칙 변경은 기존 버전을 확인하고, 계정당 규칙은 100개까지 지원한다. 운영 DB에 마이그레이션을 적용하지 않았고 운영 화면·API에도 배포하지 않았다. 프런트엔드 `NEXT_PUBLIC_SHOPPING_SHADOW_ENABLED`와 서버 `KITS_SHOPPING_SHADOW_ENABLED`는 기본 비활성이다.

2026-11-17 실제 Supabase `kits` 프로젝트에 테스트 전용 테이블과 임시 API를 설치하고 실제 로그인한 회원 및 유니킴 계정으로 테스트했다. 중지된 `01. QP1000C` / `test_01`에서 기준 60원 규칙을 저장하고 현재 50원 → 모의 60원, 보고서와 실시간 목록 일치 및 차단 사유를 확인했다. 새로고침 후 규칙과 이력도 다시 조회했다. 임시 API·테이블·테스트 데이터는 제거됐고 원자적 실행 설정은 false로 유지됐다. 해당 테스트에서 생성된 네이버 마스터 보고서 작업은 네이버에 남을 수 있다.

2026-11-17 유니킴의 중지된 `01. QP1000C` / `test_01` 그룹에서 사용자의 요청에 따라 수동 동시 변경을 검증했다. 원래 입찰가는 50원이며, 동일한 조회본을 사용한 60원·70원 API 변경 두 건이 모두 HTTP 200을 반환했고 이후 조회값은 60원이었다. 이어 존재하지 않는 `If-Match` 값을 보낸 변경도 HTTP 200이었다. 이 실험에서 사용한 일반 변경과 해당 헤더는 충돌을 차단하지 않았으며, 다른 공식 조건부 변경 기능이 존재하지 않는다는 증명은 아니다. 입찰가는 50원으로 복원하고 캠페인과 그룹이 여전히 중지 상태임을 API에서 확인했다. 임시 Edge Function은 삭제했다. 자동 실행 및 스케줄러는 중단 상태다.

2026-11-17 상품·키워드 개별 모의 규칙 경로를 로컬에서 추가했다. 연결 소유자와 선택한 캠페인·그룹·대상을 서버에서 확인하고, 대상별 규칙과 모의 이력을 저장한다. 그룹 입찰가를 상속하면 개별 입찰 전환이 필요하다는 차단 사유를 표시하며 실제 설정은 변경하지 않는다. 분리된 로컬 PostgreSQL에서 상품과 키워드 규칙 분리 및 타 사용자 접근 거부를 검증했다. 운영 DB 마이그레이션·함수·화면 배포, 실제 데이터로 개별 규칙 검증은 하지 않았다. 자동 입찰 실행 및 스케줄러는 여전히 없다.

2026-11-17 실제 Supabase Auth와 유니킴 연결 계정으로 상품·키워드별 규칙을 검증했다. 별도 테스트 화면과 임시 Edge Function, 테스트 전용 테이블/RPC를 사용했다. 쇼핑 `01. QP1000C / test_01` 상품은 50원→60원, 검색 `test / test`의 `보조배터리` 키워드는 70원→60원으로 모의 계산되었다. 두 대상 모두 규칙 저장과 이력 조회를 확인했고 결과는 execution=disabled였다. 두 대상은 그룹 입찰가를 상속해 개별 입찰 전환 필요가 표시되었다. 캠페인·그룹은 중지 상태였다. 시험용 API, 테이블 및 RPC는 삭제했고 테스트 이력 데이터도 함께 제거했다. Supabase의 테스트 설정·수정·정리 마이그레이션 기록은 남는다. 운영 화면과 API의 배포 또는 실제 입찰가 변경은 수행하지 않았다.
