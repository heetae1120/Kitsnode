# 광고주 브라우저 초대 시험 후보

이 디렉터리는 별도 설치가 필요한 Chrome 확장의 로컬 시험 후보입니다. 키츠노드 웹에서 시작하는 메시지 수신기와 네이버 탭의 광고계정 선택 후 회원 초대 정책창까지의 자동 이동이 추가됐습니다. 웹 버튼은 빌드 시 확장 ID를 설정해야 표시되며, 웹에서 자동 발송까지는 연결되지 않았습니다. 운영용 `kitsnode` 초대의 실제 동작은 검증하지 않았습니다.

광고주가 같은 브라우저에서 네이버 애즈에 직접 로그인하고 광고계정 권한 관리의 권한 받은 회원 화면을 열면, 확장 팝업에서 자동 초대를 시작할 수 있습니다. 네이버 개인정보 제공 및 회원 초대 정책은 광고주가 네이버 화면에서 직접 검토하고 동의해야 합니다. 이후 회원 ID `kitsnode` 입력, 가입 여부 조회, 운영 관리 선택과 발송을 순차 시도합니다. 발송 성공 여부는 네이버에서 직접 확인해야 하며 수락은 구현하지 않았습니다. 별도의 `jonho1` 고정 시험 빌드로 유니킴에서 실제 초대 발송을 확인했지만, 오류 수정 후 중간 화면에서 재개한 결과이며 로그인부터 운영용 대상까지의 전체 흐름을 검증한 것은 아닙니다.

비밀번호, 쿠키, 인증번호를 수집하거나 저장하지 않습니다. 로그인 후 페이지 이동을 감지하기 위해 확장 설치 시 `https://ads.naver.com/*` 호스트 접근 권한이 필요합니다. 웹 시작 요청은 `https://heetae1120.github.io/Kitsnode/store/ads/connect/`의 최상위 프레임만 받으며 네이버 로그인 탭을 여는 것만 허용합니다. 연결 식별자는 인증이나 광고계정 소유 증명이 아닙니다. 발송 직전 같은 탭과 로그인 ID를 다시 확인하고, 같은 브라우저 프로필의 동시 실행은 Web Locks로 제한합니다. 발송 시도는 광고계정 번호와 시도 시각을 브라우저 로컬 저장소에 기록하며, 결과가 불확실하면 네이버 화면에서 직접 확인해야 합니다. 이 기능은 다른 브라우저나 기기의 동시 실행을 막는 서버 예약이 아니며 서버 상태와 연결되지 않습니다. 로컬 기록을 지우거나 다른 기기에서 실행하면 중복 방지는 보장되지 않습니다. 이미 존재하던 초대와 이번 요청의 인과관계를 확인하는 기능도 없습니다. 운영 전에 계정별 서버 예약, 광고주 세션·소유 확인, 실제 네이버 UI 호환성 및 정책, 요청 결과 확인과 사용자 복구 절차가 필요합니다.

`preflight.test.mjs`는 네이버 네트워크를 차단한 가상 화면에서 URL, 고정 수신자, 권한 검사만 확인합니다. 실제 네이버 초대·수락 시험이 아닙니다.
